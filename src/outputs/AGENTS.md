# Audio Output Strategies

Factory + Strategy + Template Method pattern for audio playback targets. Each output handles delivering audio announcements to a specific device/channel.

## FILES

| File                   | Role                                                       |
| ---------------------- | ---------------------------------------------------------- |
| `BaseOutput.js`        | Abstract base — Template Method `execute()`, sidecar check |
| `OutputFactory.js`     | Factory — registration, instance management                |
| `LocalOutput.js`       | Local speaker playback (mpg123 via child_process)          |
| `BrowserOutput.js`     | Browser playback via SSE push                              |
| `VoiceMonkeyOutput.js` | Alexa playback via VoiceMonkey API                         |
| `index.js`             | Imports all strategies and registers them in OutputFactory |

## ARCHITECTURE

### Source Normalization

Callers normalize sources before calling `execute()` — outputs never normalize internally.

**Canonical source contract:**

```javascript
{ type: 'file', filePath: '/absolute/path.mp3', url: 'http://host/public/audio/path.mp3' }
{ type: 'url', url: 'http://external-host/audio.mp3' }
```

Use `normalizeSource(rawSource)` from `@utils/normalizeSource` to produce canonical sources. It handles all input shapes (`{path}`, `{filePath}`, `{url}`, `{filePath, url}`), adds path traversal protection and URL protocol validation.

### Template Method Pattern

`BaseOutput.execute()` is the **final** entry point — subclasses do NOT override it. The flow:

1. **Normalize** source via `normalizeSource()`
2. **Validate** source type against `supportedSourceTypes` from `getMetadata()`
3. **Sidecar check** (file sources only) — reads `.json` sidecar from `src/public/audio/`, checks `compatibility[outputId].valid`
4. **Dispatch** to `_executeFromFile(payload)` or `_executeFromUrl(payload)` based on `source.type`

Subclasses implement the hooks:

| Hook                        | Receives                      | Purpose                          |
| --------------------------- | ----------------------------- | -------------------------------- |
| `_executeFromFile(payload)` | `{ filePath, url, metadata }` | Handle local file audio delivery |
| `_executeFromUrl(payload)`  | `{ url, metadata }`           | Handle URL-only audio delivery   |

### Sidecar Compatibility

`BaseOutput.execute()` checks sidecar `.json` metadata before dispatching file sources. Uses `this.constructor.getMetadata().id` to look up the output-specific compatibility entry:

```json
{
  "compatibility": {
    "local": { "valid": true, "issues": [] },
    "voicemonkey": { "valid": false, "issues": ["Duration too long"] },
    "browser": { "valid": true, "issues": [] }
  }
}
```

- Sidecar missing/corrupted → **proceed** (fail-open)
- No entry for this output → **proceed**
- Explicit `valid === false` → **skip** with warning log

Sidecars are generated by `audioAssetService.enrichMetadata()` which calls each output's `validateAsset()` at indexing time.

## ADDING A NEW OUTPUT

1. Create `YourOutput.js` extending `BaseOutput`.
2. Implement `_executeFromFile(payload)` and `_executeFromUrl(payload)`.
3. Implement static `getMetadata()` returning at minimum:
   - `id` — unique string matching sidecar compatibility key (e.g., `'youroutput'`)
   - `label` — display name
   - `supportedSourceTypes` — array of `['file']`, `['url']`, or `['file', 'url']`
4. Optionally override: `healthCheck()`, `verifyCredentials()`, `validateTrigger()`, `validateAsset()`, `augmentAudioMetadata()`.
5. Register in `index.js`: import and call `OutputFactory.register('yourOutput', YourOutput)`.
6. Add output-specific config fields to `schemas.js` and secrets to `.env`.

## BaseOutput INTERFACE

| Method                       | Override?  | Purpose                                                             |
| ---------------------------- | ---------- | ------------------------------------------------------------------- |
| `execute(source, metadata)`  | **NEVER**  | Template Method — normalizes, validates, checks sidecar, dispatches |
| `_executeFromFile(payload)`  | **MUST**   | Handle file source delivery                                         |
| `_executeFromUrl(payload)`   | **MUST**   | Handle URL source delivery                                          |
| `healthCheck()`              | Optional   | Check target availability                                           |
| `verifyCredentials()`        | Optional   | Validate API keys/tokens                                            |
| `validateTrigger(trigger)`   | Optional   | Validate trigger config for this output                             |
| `validateAsset(asset)`       | Optional   | Validate audio asset compatibility (used by sidecar generation)     |
| `augmentAudioMetadata(meta)` | Optional   | Add output-specific metadata to audio files                         |
| `getMetadata()`              | **Static** | Return `{ id, label, supportedSourceTypes, ... }`                   |
| `getSecretRequirementKeys()` | **Static** | List of env var names this output needs                             |

## FACTORY USAGE

```javascript
const output = OutputFactory.getStrategy("local"); // Returns LocalOutput instance (cached)
const all = OutputFactory.getAllStrategyInstances(); // All registered instances
const secrets = OutputFactory.getSecretRequirementKeys(); // All env vars needed across outputs
```

## STRATEGY DETAILS

| Strategy            | Transport               | Source Types | Requirements                         |
| ------------------- | ----------------------- | ------------ | ------------------------------------ |
| `LocalOutput`       | `mpg123` child process  | file, url    | mpg123 installed, `/dev/snd` access  |
| `BrowserOutput`     | SSE push to frontend    | file, url    | Frontend `useSSE` + `useAudio` hooks |
| `VoiceMonkeyOutput` | HTTP to VoiceMonkey API | file, url    | `VOICE_MONKEY_TOKEN` env var         |

**LocalOutput** — mpg123 natively supports HTTP URLs, so both file and URL sources use the same `_playAudio` helper.

**BrowserOutput** — Both hooks broadcast `source.url` via SSE using a shared `_broadcastUrl` helper.

**VoiceMonkeyOutput** — `_executeFromFile` resolves the file to a URL first, then sends to API. `_executeFromUrl` sends directly. Both use `_sendToVoiceMonkey` helper.

## CONVENTIONS

- **Consumers use OutputFactory** — Never instantiate outputs directly. `automationService.js` uses the factory.
- **Callers normalize, not outputs** — Use `normalizeSource()` before calling `execute()`. The Template Method also normalizes as a safety net.
- **Secrets via env** — Output-specific API keys in `.env`, declared via `getSecretRequirementKeys()`.
- **Instance caching** — `OutputFactory.getStrategy()` caches instances. Use `_reset()` only in tests.
- **Sidecar paths** — Audio files served from `public/audio/`, sidecar metadata in `src/public/audio/` (not served by Express).
